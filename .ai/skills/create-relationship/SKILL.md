# Create Relationship Skill

Creates a many-to-many relationship between two aggregates in the **same Bounded Context**, following DDD and Hexagonal Architecture patterns.

## Input Format

The user must provide:
1. **Source aggregate** (e.g., `CriticalPoint`) — the "owner" of the relationship
2. **Target aggregate** (e.g., `ServiceCategory`) — the related entity
3. **Bounded Context** (e.g., `FoodLoss`) — must be the same for both
4. **Relationship type** (default: `many-to-many`) — currently only many-to-many is supported
5. **Update register/update** (yes/no, default: yes) — whether to add `array $targetIds = []` parameters to `register()` and `update()` methods in the source aggregate
6. **Create unlink subscriber** (yes/no, default: yes) — whether to create a `DomainEventSubscriber` that listens to `{Target}Removed` and unlinks it from all related source aggregates

If the user doesn't provide all inputs, ask for the missing information before proceeding.

## Architecture & Patterns

The relationship is implemented using an **association entity** (link entity) pattern:

- **Entidad Link** (`{Source}{Target}Link`): Plain entity with two properties: back-reference to source aggregate and a value object ID of the target
- **Collection Wrapper** (`{Source}{Target}s`): Domain-level collection class extending `ArrayCollection` to ensure Doctrine compatibility, exposes target IDs, and provides `removeById()`, `ids()`, `has()`, and overrides `contains()`
- **Domain Events**: `{Source}{Target}Linked` and `{Source}{Target}Unlinked` for event sourcing
- **Apply Methods**: `apply{Source}{Target}Linked()` and `apply{Source}{Target}Unlinked()` for event reconstruction
- **Sync Method** (optional): `syncTargets()` private method that compares current and new IDs, calling `link()` and `unlink()` as needed

All Doctrine coupling is isolated to:
- Doctrine types for target aggregate IDs (already exist)
- Doctrine mappings (XML files)
- Migrations (auto-generated by Doctrine)

The domain layer is **mostly Doctrine-free**: uses ID value objects, internal events, but pragmatically extends Doctrine's `ArrayCollection` for the collection wrapper to ensure `UnitOfWork` compatibility.

## Naming Conventions

Given source aggregate `{Source}` and target aggregate `{Target}` in context `{Context}`:

| Element | Name Pattern |
|---------|--------------|
| Link Entity | `{Source}{Target}Link` |
| Link Events | `{Source}{Target}Linked`, `{Source}{Target}Unlinked` |
| Collection Wrapper | `{Source}{Target}s` |
| Property in source | `${target_pluralized}` (e.g., `$serviceCategories`) |
| Link methods | `link{Target}()`, `unlink{Target}()` |
| IDs getter | `{target}Ids()` (e.g., `serviceCategoryIds()`) |
| Internal sync | `sync{Target}s()` (e.g., `syncServiceCategories()`) |
| Unlink subscriber | `Unlink{Target}Subscriber` (e.g., `UnlinkServiceCategorySubscriber`) |
| Filter field | `?{Target}Id $targetId` — VO, NOT string (e.g., `?ServiceCategoryId $serviceCategoryId`) |
| Doctrine mapping (link) | `{Context}.{Source}{Target}Link.orm.xml` |

## Implementation Checklist

1. **Read source and target aggregate files** to understand structure
2. **Create domain events** (`{Source}{Target}Linked.php`, `{Source}{Target}Unlinked.php`)
   - Follow pattern from existing events (e.g., `CriticalPointRegistered`)
   - Include source ID and target ID in payload
   - Implement `payload()`, `rebuildFromPayload()`, `aggregateRootId()`
3. **Create link entity** (`{Source}{Target}Link.php`)
   - Constructor with `private {Source} ${source}` and `private {Target}Id ${targetId}`
   - Simple getters for both
4. **Create collection wrapper** (`{Source}{Target}s.php`)
   - Class-level PHPDoc: `/** @implements \IteratorAggregate<int, {Source}{Target}Link> */`
   - Implements: `\IteratorAggregate, \Countable` (composition over inheritance — does NOT extend `ArrayCollection`)
   - Private property: `/** @var Collection<int, {Source}{Target}Link> $items */ private Collection $items;`
   - Constructor: `/** @param iterable<int, {Source}{Target}Link> $items */ public function __construct(iterable &$items)` — takes by reference, normalizes to `ArrayCollection` if not already a `Collection`, assigns to `$this->items`
   - Methods: `removeById()`, `ids()`, `has()`, `count()`, `getIterator()`
   - `ids()` return type PHPDoc: `/** @return {Target}Id[] */`, iterates over `$this->items->toArray()`
   - `has({Target}Id $id): bool`: checks if the ID exists in `$this->items->toArray()`
   - `removeById({Target}Id $id): void`: iterates `$this->items->toArray()`, calls `$this->items->removeElement()` on match
   - `count(): int`: delegates to `$this->items->count()`
   - `getIterator(): \Traversable`: delegates to `$this->items->getIterator()`
5. **Modify source aggregate** (`{Source}.php`)
   - Add property typed as `iterable` (NOT the wrapper class): `private iterable ${target_pluralized} = []`
     - **Why `iterable`**: Doctrine hydrates the field with its own `PersistentCollection`; the property must remain `iterable` so Doctrine can hydrate it freely
   - Add PHPDoc above the property: `/** @var iterable<int, {Source}{Target}Link> */`
   - Add public getter: `{target_pluralized}(): {Source}{Target}s` — creates a new wrapper on every call: `return new {Source}{Target}s($this->{target_pluralized});`. The by-reference constructor normalizes the property to a `Collection` on first call, so subsequent wrappers still point to the same underlying `PersistentCollection`
   - Add public getter: `{target}Ids(): array` with `/** @return {Target}Id[] */`
   - Add `link{Target}({Target}Id $id)`: guard with `has()` check before firing event
   - Add `unlink{Target}({Target}Id $id)`: guard with `!has()` check before firing event (symmetric with link)
   - Add apply methods: `apply{Source}{Target}Linked()`, `apply{Source}{Target}Unlinked()`
   - If updating register/update: add `/** @param {Target}Id[] */ array $targetIds = []`, call private `sync{Target}s($targetIds)` at the end
6. **Create Doctrine mapping (link)** (`{Source}.{Source}{Target}Link.orm.xml`)
   - Entity with composite primary key: `critical_point_id` (association-key) + `target_id` (custom type)
   - many-to-one relationship back to source with inversed-by and ON DELETE CASCADE
7. **Modify Doctrine mapping (source)** (`{Source}.{Source}.orm.xml`)
   - Add one-to-many relationship to link entity with mapped-by, cascade-persist, cascade-remove, fetch=EXTRA_LAZY
8. **Modify Application layer** (Register and Update use cases, if register/update was updated)
   - **`Register{Source}Request`** and **`Update{Source}Request`**:
     - Add `use` for `{Target}Id`
     - Add `/** @param {Target}Id[] $targetIds */` PHPDoc on constructor
     - Add `public array ${target}Ids = []` parameter
   - **`Register{Source}Service`** and **`Update{Source}Service`**:
     - Pass `{target}Ids: $request->{target}Ids` to the domain method call
     - Pass `{target}Ids: ${source}->{target}Ids()` to the response constructor
   - **`Register{Source}Response`** and **`Update{Source}Response`**:
     - Add `use` for `{Target}Id`
     - Add `/** @param {Target}Id[] $targetIds */` PHPDoc on constructor
     - Add `public array ${target}Ids = []` parameter — default `[]` to avoid breaking existing callers
9. **Add `?{Target}Id` to `{Source}Filter`** (required by the subscriber and useful for future queries)
   - Add `use` for `{Target}Id`
   - Add `public ?{Target}Id $targetId = null` — use the VO directly, **never `?string`**
   - **`InMemory{Source}Repository`**: add filter block using `$id->equals($filter->{target}Id)`
   - **`Doctrine{Source}Repository`**: add `JOIN e.{target_pluralized} sc` + `WHERE sc.{target}Id = :id` with `setParameter(..., (string) $filter->{target}Id)` — cast to string only at the Doctrine boundary
10. **Create unlink subscriber** (`src/{Context}/Domain/Event/{Target}/Unlink{Target}Subscriber.php`)
    - Implements `DomainEventSubscriber`, uses `RegisterTrait`
    - Constructor: `private {Source}Repository ${source}Repository`, calls `$this->register()`
    - `isSubscribedTo()`: `return $event instanceof {Target}Removed`
    - `handle()`: assert + delegate to private `handle{Target}Removed()`
    - `handle{Target}Removed()`: `findByFilter(new {Source}Filter({target}Id: $event->{target}Id(), limit: 0))`, then for each: `unlink{Target}()` + `add()`
11. **Modify UI forms and controllers**
    - **`List{Source}sType`**: add `{Target}IdType` field with `required: false` (single selection, for the filter form)
    - **`Register{Source}Type`**: add `{Target}IdType` field with `multiple: true, required: false`; pass explicit `new Register{Source}Request()` to `createForm()` in the controller — **critical**: without this, the `multiple` field receives `null` instead of `[]` and the transformer throws `Expected an array`
    - **`Update{Source}Type`**: add `{Target}IdType` field with `multiple: true, required: false`
    - **`RegisterController`**: `$this->createForm(Register{Source}Type::class, new Register{Source}Request())` — always pass the explicit DTO instance
    - **`EditController`**: when building the pre-filled `Update{Source}Request` DTO, include `{target}Ids: ${source}->{target}Ids()` — without it the form renders with nothing selected even if the entity has linked targets
    - **`register.html.twig`**: if it extends the shared `@shared/layout/register.html.twig`, no change needed — that layout iterates `{% for field in form %}` and renders all fields automatically
    - **`edit.html.twig`**: add `{{ form_row(form.{target}Ids) }}` explicitly since edit templates render each field manually
    - **Filter UI (Twig Extension & FilterBar)**:
      - Create `{Target}Extension.php` in `src/{Context}/Infrastructure/Symfony/Twig/` with a `{target}_name` filter (if it doesn't exist) to resolve the ID to the entity name.
      - Modify `templates/components/List/FilterBar.html.twig`: add `{% elseif field == '{target}Id' %}` `{% set value = value | {target}_name %}` and `{% elseif field == '{target}Ids' %}` `{% set value = value | map(v => v | {target}_name) | join(', ') %}` so the filter bar shows human-readable names instead of UUIDs.
12. **Generate and run migration**
    - `make migration` auto-generates the join table
    - Fill in `getDescription()` with a meaningful description (auto-generated leaves it empty)
    - `make migrate` applies it
12. **Update PHPStan config** if needed (collection type mismatch warnings are already ignored globally)
13. **Run validation**
    - `make phpstan` — no errors
    - `make test` — all tests pass
    - `make cs-fix` — coding standards

## Key Design Decisions

- **Link entity in domain** (not infrastructure): The link is a domain concept because it's part of the aggregate boundary and event sourcing
- **ID-only references**: Collection wrapper exposes only target IDs, never full aggregate objects — maintains aggregate isolation
- **Composition over inheritance**: Collection wrapper implements `\IteratorAggregate, \Countable` and wraps a `Collection` internally — it does NOT extend `ArrayCollection`. This keeps the domain class free of Doctrine coupling while still delegating to the underlying `PersistentCollection`.
- **By-reference constructor normalization**: The wrapper constructor takes `iterable &$items` by reference and converts it to an `ArrayCollection` if it is not already a `Collection`. This mutates the aggregate's property in-place on first access, so the Doctrine `PersistentCollection` is preserved and `removeElement()` calls continue to be tracked by Doctrine's `UnitOfWork`.
- **New wrapper per call, same underlying collection**: The getter returns `new {Source}{Target}s($this->{target_pluralized})` on every call. Because the constructor normalizes the reference on the first call, all subsequent wrapper instances share the same underlying `Collection`, so mutations (add/remove) remain consistent.
- **Symmetric guards**: Both `link{Target}()` and `unlink{Target}()` guard against no-ops — link checks `has()` before firing, unlink checks `!has()` before firing. This prevents spurious domain events when calling them directly (outside of `sync{Target}s`)
- **Sync method**: Optional but recommended — allows register/update to accept `{target}Ids` and sync links automatically via link/unlink events
- **Filter uses VO, not string**: `{Source}Filter::${target}Id` is typed `?{Target}Id`, never `?string`. The VO allows `equals()` in InMemory and is cast to `(string)` only at the Doctrine `setParameter()` boundary
- **Unlink subscriber**: `Unlink{Target}Subscriber` listens to `{Target}Removed` and calls `findByFilter(limit: 0)` + `unlink{Target}()` + `add()` for each linked source. Uses `limit: 0` to bypass pagination and retrieve all matches
- **`multiple` field needs explicit DTO in `createForm()`**: `ChoiceType` with `multiple: true` requires the bound data to be an array. If `createForm()` is called without a pre-built DTO (only the class string), Symfony may resolve a null for the array property, causing `AggregateRootIdTransformer::transform(null)` to return `''` instead of `[]`, which fails with `Expected an array`. Always pass `new Register{Source}Request()` explicitly.
- **Edit controller must pre-populate target IDs**: the pre-filled `Update{Source}Request` DTO must include `{target}Ids: ${source}->{target}Ids()`. Omitting it renders the multi-select with nothing selected, silently losing all existing links on save.

## Caveats & Limitations

- **Same Bounded Context only**: Cross-context relationships must use ID references, not full aggregates
- **Pragmatic Doctrine coupling**: The wrapper uses composition (implements `\IteratorAggregate, \Countable`) and normalizes the aggregate's `iterable` property to a `Collection` via a by-reference constructor. This preserves the Doctrine `PersistentCollection` reference so `UnitOfWork` tracking continues to work without extending any Doctrine class.
- **Many-to-many only**: One-to-many and one-to-one are out of scope; implement those patterns manually if needed
- **No cascade operations from target at DB level**: The join table uses ON DELETE CASCADE only for the source side. Removing a `{Target}` does not automatically unlink at the DB level — that is handled by `Unlink{Target}Subscriber` at the domain level

## Testing

- Ensure existing unit tests for the source aggregate still pass
- Acceptance tests should exercise register/update with target IDs if those methods are updated
- Add `{Source}Mother::withServiceCategories({Target}Id ...$ids)` factory method for subscriber and filter tests
- **Subscriber test** (`tests/Unit/{Context}/Domain/Event/{Target}/Unlink{Target}SubscriberTest.php`):
  - `testIsSubscribedTo{Target}Removed()` — asserts `isSubscribedTo()` returns true for the right event
  - `testIsNotSubscribedToOtherEvents()` — asserts false for an unrelated event
  - `testHandleUnlinks{Target}FromAllLinked{Source}s()` — creates sources with the target linked (including one with multiple targets), handles the event, asserts the specific target is removed while others remain
  - `testHandleDoesNothingIfNoLinked{Source}s()` — empty filter result, no error
  - Use `$repository->find($id)` result stored in a variable before assertions — PHPStan requires `assertNotNull()` before calling methods on a nullable return
- **Acceptance tests** — add to both `{source}-register.feature` and `{source}-edit.feature`:
  - `Then I see a form field "serviceCategoryIds"` — verifies the field is rendered (requires `iSeeAFormField` step in `WebContext` using `$crawler->filter('[name*="{name}"]')`)
  - Submit scenario with array syntax: `serviceCategoryIds:[id1,id2]` — the `iSubmitAFormWith` step parses `[...]` values as arrays automatically
  - `WebContext::iSeeAFormField(string $name)`: `$crawler->filter(sprintf('[name*="%s"]', $name))` + `assertGreaterThan(0, $field->count())`
